# Releasing MyShelf

MyShelf is released as Android APKs and an App Bundle (AAB) on [GitHub Releases](https://github.com/asorichetti/MyShelf/releases), built for free ([ADR 0011](adr/0011-free-android-release-pipeline.md)). There are three ways to build a release, all from the same configuration:

| Where | Cost | Needs |
|---|---|---|
| [GitHub Actions](#from-ci-github-actions) (`.github/workflows/release.yml`) | free for a public repository | nothing on your machine |
| [Your machine](#locally-with-the-android-sdk) (`expo prebuild` + Gradle) | free | JDK 17 and the Android SDK |
| [EAS Build](#with-eas) | free tier (limited builds a month), or free with `--local` | an Expo account |

`android/` is generated by `npx expo prebuild` and git-ignored: every native setting lives in `app.json` and the config plugins (`plugins/`), never in hand edits.

## Versions

- **`version`** in `app.json` is the name users see (`1.2.3`, or `1.2.3-rc1` for a release candidate).
- **`android.versionCode`** must grow with every build installed over another. It is worked out from the version:

  `versionCode = major × 1,000,000 + minor × 10,000 + patch × 100 + (rc number, or 99 for the release)`

  so `v0.9.0-rc1` → 90001, `v1.0.0-rc2` → 1000002, `v1.0.0` → 1000099, `v1.0.1` → 1000199. A release candidate sorts below its release, and a tag builds to the same code everywhere. Minor and patch go up to 99; release candidates are numbered 1–98.
- **The tag is the version.** The release workflow runs `node scripts/release-version.mjs "$TAG" --write`, which sets both fields in its copy of `app.json`. To build a tagged version by hand, run the same command first (and do not commit the result unless you are bumping the version for real).
- Between releases `app.json` keeps the last released version (and `versionCode` 1 before the first), so a build from a branch installs as that version.

## Signing

Android only installs an update signed with the same key as the installed app, so the **upload key** is the one thing that must never be lost or published.

- Release builds are signed by `plugins/withReleaseSigning.js`, which adds a `release` signing config to the generated `android/app/build.gradle`. It reads four values from Gradle properties (`-P…` or `~/.gradle/gradle.properties`) or, failing that, environment variables:

  | Name | Value |
  |---|---|
  | `MYSHELF_UPLOAD_STORE_FILE` | path to the keystore file |
  | `MYSHELF_UPLOAD_STORE_PASSWORD` | keystore password |
  | `MYSHELF_UPLOAD_KEY_ALIAS` | key alias |
  | `MYSHELF_UPLOAD_KEY_PASSWORD` | key password |

- Without `MYSHELF_UPLOAD_STORE_FILE` the release build is signed with the **debug key** that `expo prebuild` generates. That APK installs and runs like the real thing, so it is fine for sideloading and testing, but it cannot replace (or be replaced by) a signed install, and Google Play rejects it. CI names these files `…-debug-signed.apk` / `.aab`.
- Keystores (`*.jks`, `*.keystore`, their base64 form) and EAS `credentials.json` are git-ignored. Never commit one, paste one into an issue, or print a password in a workflow log.

### Create the upload keystore (once)

```bash
keytool -genkeypair -v -storetype PKCS12 \
  -keystore myshelf-upload.keystore -alias myshelf-upload \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -dname "CN=MyShelf, O=asorichetti"
```

`keytool` comes with any JDK. It asks for a password; for a PKCS12 keystore the key password is the same one. Then:

1. **Back it up offline** (a password manager plus an encrypted USB stick): the file, the alias and the password. Losing it means installed copies can never be updated.
2. Print the certificate fingerprints (needed to restrict a Google Books API key to this app, or to register with Google Play):

   ```bash
   keytool -list -v -keystore myshelf-upload.keystore -alias myshelf-upload
   ```

### Store it as GitHub secrets

With the [GitHub CLI](https://cli.github.com), from the repository folder:

```bash
base64 -i myshelf-upload.keystore | gh secret set ANDROID_KEYSTORE_BASE64   # Linux: base64 -w0 myshelf-upload.keystore | …
gh secret set ANDROID_KEYSTORE_PASSWORD    # prompts for the value
gh secret set ANDROID_KEY_ALIAS --body myshelf-upload
gh secret set ANDROID_KEY_PASSWORD         # the same password for PKCS12
```

Or in the browser: **Settings → Secrets and variables → Actions → New repository secret**, one per name. Optional: `GOOGLE_BOOKS_API_KEY`, a Google Books API key built into the app (below).

## From CI (GitHub Actions)

`.github/workflows/release.yml` runs the regression gate (`npm run check`, the auto test suite's checks, smoke and every journey with gates set to fail), then on an Ubuntu runner:

1. `npm ci`, Java 17 (Temurin), and the NDK, build tools and platform that React Native's version catalog (`node_modules/react-native/gradle/libs.versions.toml`) asks for.
2. `scripts/release-version.mjs` (on a tag: writes the tag's version into `app.json`).
3. Decodes the keystore from the secrets into the runner's temporary folder, or warns and carries on debug-signed.
4. `npx expo prebuild --platform android --clean`, then in `android/` `./gradlew bundleRelease` and `./gradlew assembleRelease -PmyshelfApkAbis=arm64-v8a,armeabi-v7a` (two runs: with resource shrinking on, the Android Gradle plugin will not build per-ABI APKs and a bundle in one) (Gradle's caches are kept between runs by `gradle/actions/setup-gradle`).
5. Uploads `myshelf-<version>-<signed|debug-signed>-arm64-v8a.apk` and `…-armeabi-v7a.apk`, the `.aab` and a `.sha256` of all three as workflow artifacts (kept 30 days). The run's summary lists the checksums, the signing certificate and the permissions in the APK.
6. **On a tag only:** creates a **draft** GitHub Release named after the tag (marked pre-release when the tag has a `-rc` part) with the files attached. The notes are the version's section of `CHANGELOG.md` (`## [1.2.3]`, `## 1.2.3` or `## v1.2.3`), or else the annotated tag's message (`scripts/release-notes.mjs`). Check it, then press **Publish**. Re-running a tag's workflow replaces the files on its draft.

### Which file to install

| File | For | Size (1.0.0, 27 September 2026) |
|---|---|---|
| `…-arm64-v8a.apk` | sideloading on any phone from the last ten years (64-bit ARM) | 60.7 MB to download, about 80 MB installed |
| `…-armeabi-v7a.apk` | sideloading on an old 32-bit phone | 46.9 MB to download |
| `….aab` | Google Play only (it cannot be installed directly) | 110 MB, all four ABIs; Play sends each phone only its own part |

Two things keep the APKs small:

- **One APK per ABI** (`plugins/withApkAbiSplits.js`, switched on by the Gradle property `-PmyshelfApkAbis=arm64-v8a,armeabi-v7a`). A universal APK carries the native code for all four ABIs React Native builds: 179 MB to download and about 190 MB installed. The App Bundle is unaffected: it stays universal, and Google Play splits it per device. If unsure, `adb shell getprop ro.product.cpu.abi` names a phone's ABI; practically every phone in use today is `arm64-v8a`.
- **R8 shrinking** of code and resources (`plugins/withReleaseShrinking.js`): without it the arm64-v8a APK was 72.3 MB and about 120 MB installed, most of it library classes Android also compiles on install. Libraries ship their own keep rules; the Maestro suite runs on the shrunk build, so a class R8 wrongly removes would show up there ([`device-testing.md`](device-testing.md)).

**Release a version:**

```bash
git switch main && git pull
git tag -a v1.0.0 -m "MyShelf 1.0.0"
git push origin v1.0.0
```

**Test build of any branch:** Actions → **Release** → **Run workflow** → choose the branch → leave **Sign** ticked to use the upload key (when the secrets exist) or untick it for a debug-signed build. Or from a terminal:

```bash
gh workflow run release.yml --ref <branch> -f sign=false
gh run list --workflow release.yml --limit 1        # note the run id
gh run watch <run-id>
gh run download <run-id>                            # the APKs, the AAB and the checksums
```

A dispatched run uses the version already in `app.json` and never creates a Release.

## Before a release

Run the device regression on the release candidate and note the result in the release pull request: the checklist is in [`device-testing.md`](device-testing.md#regression-checklist-p09-10) (the Maestro suite on an emulator or the **Android E2E** workflow, a physical phone, the real camera, TalkBack, offline, an upgrade over the previous release, the production APK's first run).

## Locally, with the Android SDK

Prerequisites: **JDK 17** (e.g. Temurin), the **Android SDK** with the platform, build tools and **NDK** versions listed in `node_modules/react-native/gradle/libs.versions.toml` (`compileSdk`, `buildTools`, `ndkVersion`; Android Studio's SDK Manager installs them), and `ANDROID_HOME` pointing at the SDK.

```bash
npm ci
node scripts/release-version.mjs v1.0.0 --write      # optional: build as a given version
npx expo prebuild --platform android --clean

export MYSHELF_UPLOAD_STORE_FILE=/secure/path/myshelf-upload.keystore
export MYSHELF_UPLOAD_KEY_ALIAS=myshelf-upload
read -rs MYSHELF_UPLOAD_STORE_PASSWORD && export MYSHELF_UPLOAD_STORE_PASSWORD
export MYSHELF_UPLOAD_KEY_PASSWORD="$MYSHELF_UPLOAD_STORE_PASSWORD"

(cd android && ./gradlew assembleRelease bundleRelease)
```

Skip the `export`s for a debug-signed build. The results are `android/app/build/outputs/apk/release/app-release.apk` (universal) and `android/app/build/outputs/bundle/release/app-release.aab`. Install the APK with `adb install -r android/app/build/outputs/apk/release/app-release.apk`. Run `./gradlew assembleRelease -PmyshelfApkAbis=arm64-v8a,armeabi-v7a` on its own for one APK per ABI as CI builds them (`app-arm64-v8a-release.apk`, …; not in the same run as `bundleRelease`, which the Android Gradle plugin refuses while resources are shrunk), or `-PreactNativeArchitectures=arm64-v8a` to build only the 64-bit ARM native code (much faster, and all a modern phone needs).

**A test APK in one command:** `scripts/build-android-apk.sh production` (what users get) or `scripts/build-android-apk.sh e2e` (with the fixture loader, for Maestro only) runs the prebuild and Gradle steps above for arm64-v8a and copies the result to `build/myshelf-<kind>.apk`; `ABIS=all` builds the universal APK, `ABIS=x86_64` one for an Intel emulator. See [`device-testing.md`](device-testing.md). Check the signature with `$ANDROID_HOME/build-tools/<version>/apksigner verify --print-certs <apk>`.

Instead of environment variables, the four `MYSHELF_UPLOAD_*` values can go in `~/.gradle/gradle.properties` (outside the repository).

## With EAS

`eas.json` profiles:

| Profile | Output | Use |
|---|---|---|
| `preview` | release APK | sideloading and testing |
| `production` | release AAB | Google Play |
| `e2e` | release APK with `EXPO_PUBLIC_E2E=1` (the fixture loader) | Maestro flows only; never distribute |

`cli.appVersionSource` is `local`: EAS uses `version` and `versionCode` from `app.json`, so run `scripts/release-version.mjs <tag> --write` first.

```bash
npx eas-cli@latest build --platform android --profile preview           # on Expo's servers (free tier)
npx eas-cli@latest build --platform android --profile preview --local   # on your machine, needs the Android SDK
```

EAS keeps its own signing credentials. To sign with the same upload key as CI, choose it when EAS asks, or run `npx eas-cli@latest credentials` and upload `myshelf-upload.keystore`; otherwise EAS-signed and CI-signed builds cannot update each other.

## The optional Google Books key

`EXPO_PUBLIC_GOOGLE_BOOKS_API_KEY` is read at **build time** and compiled into the app (it is not a secret once shipped: anyone can extract it from the APK). Locally it comes from `.env.local`; on CI from the `GOOGLE_BOOKS_API_KEY` secret; on EAS from an EAS environment variable. Restrict the key in Google Cloud to the Books API and to Android apps with package `dev.asorichetti.myshelf` and the upload key's SHA-1 fingerprint. Without a key, the app uses Open Library and keyless Google Books (see `PLAN.md` §6).

## Android permissions

`app.json` lists what the app asks for and blocks (`android.blockedPermissions`, which removes them from the merged manifest) what libraries would otherwise add:

| Permission | Why |
|---|---|
| `CAMERA` | scanning barcodes and photographing covers (asked for on first use of the Scan tab or "Take a photo") |
| `INTERNET`, `ACCESS_NETWORK_STATE` | book details and covers from Open Library and Google Books; knowing whether the phone is on mobile data |
| `POST_NOTIFICATIONS` (Android 13+), `RECEIVE_BOOT_COMPLETED` | optional loan reminders, and keeping them scheduled after a restart |
| `VIBRATE` | a short buzz when a barcode is read |
| `WRITE_EXTERNAL_STORAGE` (Android 12 and older only) | declared by `expo-image-picker`, which asks for it before opening the camera on Android 9 and older |

Blocked: `READ_EXTERNAL_STORAGE`, `READ_MEDIA_*`, `ACCESS_MEDIA_LOCATION` (the photo picker and file picker need no permission), `RECORD_AUDIO`, `SYSTEM_ALERT_WINDOW`, `ACCESS_WIFI_STATE`, `com.google.android.gms.permission.AD_ID` and `com.google.android.c2dm.permission.RECEIVE` (no ads, no push), `com.google.android.finsky.permission.BIND_GET_INSTALL_REFERRER_SERVICE` (the Play install referrer: no attribution tracking), and `READ_APP_BADGE` plus the launcher badge permissions the notification library adds for Samsung, Huawei, Sony, HTC, Oppo and other launchers (MyShelf never shows a badge count). The last two groups were found in the first CI-built APK's merged manifest. `android.allowBackup` is `false`, so Android's automatic cloud backup does not copy the library; backups are the user's own exports ([ADR 0012](adr/0012-local-only-data.md)).

After changing plugins or dependencies, check the result: the CI run's summary lists the permissions in the built APK (`aapt2 dump permissions`), and `npx expo prebuild --platform android` shows the app's own manifest in `android/app/src/main/AndroidManifest.xml`.

## The bundled text-recognition model

Reading covers (P03-05) uses ML Kit Text Recognition v2 with its **bundled Latin model** (`com.google.mlkit:text-recognition:16.0.1`, added by the local module in `modules/text-recognition`), not the thin variant that downloads the model through Google Play services: covers can be read offline, from the first launch, on phones without Play services. The price is size. Measured on 26 September 2026 with two release APKs built for `arm64-v8a` only (`./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a`), identical except for the module:

| Build | APK size |
|---|---|
| without the text-recognition module | 59.7 MB |
| with it | 72.3 MB (**+12.6 MB**, +21 %) |

These are from before release builds were shrunk with R8 (above); the module's cost is native code and model files, which R8 leaves as they are.

The increase is the native OCR library (`libmlkit_google_ocr_pipeline.so`, 11.1 MB for `arm64-v8a`) and the models (about 1.5 MB in `assets/mlkit-google-ocr-models/`). The library is per ABI: 6.8 MB for `armeabi-v7a`, 11.6 MB for `x86` and `x86_64`, so an APK for all four ABIs grows by about 42 MB, while an App Bundle download from Google Play grows by one ABI's share (about 12.6 MB on a 64-bit ARM phone). The module adds no Android permission (`aapt2 dump permissions` is unchanged). Like the barcode scanner's bundled ML Kit model, it may send Google diagnostic information, never the images or the words read (see [privacy.md](privacy.md#camera-and-photos)).
